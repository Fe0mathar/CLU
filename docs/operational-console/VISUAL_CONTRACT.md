# Operational Console Visual Contract

## Visual objective

A high-fidelity cinematic command surface that remains technically trustworthy at all times.

## Palette

```text
#000000  Black foundation
#00a3e0  Neon Blue — system traffic and verified neutral state
#f4af2d  CLU-E Gold — proof, selection, authoritative emphasis
#ff5500  Orange/Red — warning, failure, invalid evidence
#39ff88  Green — temporary shadow-application state only
```

## Layout

```text
Top rail: identity, live channels, connection state
Current work: WHAT / WHY / HOW PROVEN / WHO-MODEL / CURRENT / NEXT
Main viewport: grouped exact send / receive / interpretation traffic
Footer: CLU-E STATUS, pause, auto-scroll, sequence/seal readout
Drawer: full redacted artifact
```

## Cinematic behavior

Allowed:

- transmission pulses triggered by actual outbound events;
- return pulses triggered by actual inbound events;
- benchmark corridor animation while a real benchmark request is outstanding;
- gold stabilization only after validation/admissibility;
- orange fracture on real warning/error/rejection;
- subtle grid, scanline, glass, bloom, and parallax effects.

Forbidden:

- fake typing;
- fake code;
- fake percentages;
- fake benchmark progress;
- fake responses;
- animation implying proof before a proof event exists;
- reordering events for drama.

## Text fidelity

The WebGPU canvas supplies atmosphere and real-event activity signals. DOM text remains the authoritative readable layer because code, commands, IDs, hashes, and evidence must remain crisp and selectable.
